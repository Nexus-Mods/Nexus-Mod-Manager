## Small design choice and implemented scope

A single subclass is the smallest opt-in seam: adding `IReviewedBasicInstallMappingProvider` directly to every generic mode would change native installer dispatch for existing games. The shared host implements that interface only for `managed-content`. The existing Witcher subclass composes the same provider and keeps its compatibility/edition/native-authority boundary; its profile migration is deferred.

The new `ManagedContentLayoutPlanner` in ModManager.Interface captures immutable rules, exact files, rule/component provenance, ignored files, blockers and a SHA-256 identity bound to provider/revision/configuration, source selection, package identity, name and install method/root. Component identity is descriptive; native per-file owners remain authoritative. There are no file reads/writes in this evaluator. Configured raw names use the same hash/stem contract as the old Witcher planner.

The shipped Witcher JSON now declares Mods, DLC, bare mod/DLC and raw content rules. The adapter requires configured output to match its characterized mapper exactly, so JSON cannot widen the supported native Witcher subset. Activation remains false and order writes remain gated. The JSON-only `GameModes/Templates/ManagedContentSample/game.json` proves the same evaluator with `Packages/pkg*/assets` and raw `assets`, using the ordinary factory and native basic-plan builder with no new sample-specific class.
